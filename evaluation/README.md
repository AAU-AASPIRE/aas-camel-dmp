# Evaluation

Reproduces the paper's two experiments. Each command runs every system it compares and ends with the figure
and the data it plots.

| Experiment | Compares | Full run | `--quick` |
| --- | --- | --- | --- |
| `experiments/northbound.yaml` | Device → AAS latency against payload size: the DMP, Eclipse BaSyx DataBridge, nodered-dmp and a direct PATCH as reference | ~2.5 h | ~15 min |
| `experiments/southbound.yaml` | AAS → device: Property writes and Operation calls through BaSyx and the DMP, against the device's native interface | ~40 min | ~20 min |

## Requirements

Docker with Compose v2, [uv](https://docs.astral.sh/uv/), 8 or more cores, about 4 GB of free memory and no
other containers running. For stable numbers, set the CPU governor to `performance`.

## Redraw the paper's figures

`paper/` holds what the paper's figures are drawn from: each experiment's `summary.json`, the figure, its data
and the run's `manifest.json` (commit, images, host).

```bash
uv run python -m analysis.figures paper/northbound
uv run python -m analysis.figures paper/southbound
```

## Run the experiments

```bash
uv run python -m harness.run experiments/northbound.yaml --quick   # check the setup first
uv run python -m harness.run experiments/northbound.yaml
uv run python -m harness.run experiments/southbound.yaml
```

Each run writes `results/<experiment>/<UTC time>/` with the figure, its data, every point's samples and logs, and
a `manifest.json`. `uv run python -m analysis.figures <run folder>` redraws the figure, and
`uv run python -m analysis.publish <run folder>` copies the figure and its data into `paper/`.

Options: `--dry-run` lists the points, `--resume <run folder>` completes an interrupted run, `--dmp-image <image>`
measures a prebuilt DMP image (by default the runner builds one from this checkout), `--keep-captures` keeps
each point's packet capture (deleted once its latencies are extracted).

`SUT_CPUSET`, `INFRA_CPUSET` and `TOOLS_CPUSET` pin the system under test, the infrastructure and the tools to
separate cores. By default each of the first two gets a quarter of the cores and the tools get the rest. Absolute
numbers depend on the hardware, so compare systems on the same host.

## Layout

`harness/` runs the experiments, `adapters/` deploys each system, `tools/` holds the load generator, device
simulator and observers, and `analysis/` turns samples into figures. `test_aas/` holds the scenarios' AAS
environments, generated by `../fixtures/scenarios.py`.
